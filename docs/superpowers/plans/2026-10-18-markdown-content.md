# Markdown Content System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate every site page from markdown in `content/`, with a local `dev` command that rebuilds and reloads on save, and all project pages under `/projects/<slug>/`.

**Architecture:** `tools/site.mjs` is a CLI over small ES modules in `tools/lib/`. `content.mjs` loads and validates `content/site.md` and `content/projects/*.md`. `markdown.mjs` renders bodies with the media extras. `templates.mjs` holds pure page functions that return HTML strings. `build.mjs` turns content into a `Map<relPath, html>`, and writes or diffs it. `dev.mjs` serves, watches and live-reloads. The existing CSS and browser JS stay hand-written and unchanged.

**Tech Stack:** Node 26 (ESM `.mjs`), `marked@12.0.2`, `yaml@2.4.2`, `node:test`; no other dependencies.

**Spec:** `docs/superpowers/specs/2026-10-18-markdown-content-design.md`

## Global Constraints

- `package.json` has no `"type": "module"`. `assets/js/*.js` stay CommonJS-testable, and tools use `.mjs`. Dependencies are pinned exactly (`"marked": "12.0.2"`, `"yaml": "2.4.2"`). `node_modules/` is git-ignored.
- Generated output must match the current `redesign` branch markup and behavior (same classes, scripts, nav, title screen, filters, reveal fallback script, view transitions), apart from project URLs moving to `/projects/<slug>/`.
- Every generated HTML file starts with `<!-- Generated by tools/site.mjs from <source> — edit that file, not this one. -->` immediately after `<!doctype html>`.
- Slugs: `^[a-z0-9]+(-[a-z0-9]+)*$`. Migration slugs: `cafebabe-pekora`, `painterly-shader`, `ramu-cinematic`, `mocap-addon`, `a-gentelmans-dispute`, `decent-farewell`, `kungfu-penguin`, `ginger-air`, `mask-exe`.
- Text is migrated verbatim, including Victor's spelling.
- Missing optional fields render nothing. Missing `what_i_did` and `summary` keep the `<!-- TODO(victor): what I did -->` comments.
- The dev reload script is injected only by the dev server's responses, never written to disk.
- `check` compares against the working tree with CRLF normalized to LF.
- Old URLs redirect: `/artwork/<n-slug>/` and `/games/<n-slug>/` go to `/projects/<slug>/`, and `/artwork/` goes to `/work/`. `/games/` is the Games listing.
- The sitemap keeps the `posts/` and `welcome-to-my-site/` entries.

## Review Focus

1. **Content errors while `dev` is running** (bad YAML, unknown filter key, missing asset path, duplicate slug): the message names the file and the field, the server keeps running, and the browser shows the error. (Test in Task 1 for the messages; Task 4 for dev surviving.)
2. **Editor double-writes / half-written files on save:** rebuilds are debounced, and a parse failure mid-save doesn't crash or wipe output. (Task 4.)
3. **Hand edit to a generated file:** `check` fails and names the file; `build` restores it. (Task 4.)
4. **Windows line endings:** a CRLF checkout must not make `check` fail. (Task 4.)
5. **A new project made with `new`** builds immediately with only a title filled in. (Task 4.)

**Interfaces:**
- Produces: `loadContent(contentDir: string, { assetRoot: string }): { site: Site, projects: Project[] }`, which throws `ContentError` on any problem.
- `Site = { filters: Array<{key, label}>, highlights: string[] /*slugs*/, titleRole: string, aboutMarkdown: string }`
- `Project = { slug, source /*'content/projects/x.md'*/, title, type: 'work'|'game', label, categories: string[], tags: string[], summary, description, thumbnail, preview?, hero, heroPoster?, heroCaption?, facts: Array<[key, value]>, links: Array<{text, url}>, order: number, whatIDid?: string, highlightImage?, highlightVideo?, body: string }`. Projects are sorted by `order`, then `slug`. `description` defaults to `summary`.
- `class ContentError extends Error { file; field }`. The message format is `<file>: <field>: <problem>`.
- `parseFrontMatter(text): { data, body }` (YAML between leading `---` lines; CRLF tolerated).

### Task 4: CLI — build, check, new, dev

**Files:**
- Create: `tools/site.mjs`, `tools/lib/dev.mjs`, `tools/templates/new-project.md`, `tests/cli.test.mjs`
- Modify: `package.json` scripts: `"dev": "node tools/site.mjs dev"`, `"build": "node tools/site.mjs build"`, `"check": "node tools/site.mjs check"`, `"test": "node --test tests/*.test.mjs"`

**Interfaces:**
- `node tools/site.mjs build`: prints the count of files written, exit 0. On a ContentError it prints the message and exits 1.
- `node tools/site.mjs check`: exit 0 when `diffSite` is empty, otherwise lists the paths and exits 1.
- `node tools/site.mjs new <slug>`: writes `content/projects/<slug>.md` from the template, with the title derived from the slug. It refuses an existing file or a bad slug (exit 1).
- `node tools/site.mjs dev [--port 8000]`: builds, serves the repo root over HTTP, and watches `content/`, `tools/` and `assets/`. Rebuilds are debounced to 150ms, writing only changed files. HTML responses get `<script>new EventSource('/__reload').onmessage=()=>location.reload()</script>` injected before `</body>`. On a ContentError it keeps serving and sends an error overlay page as the response for HTML requests until fixed. If the port is busy it tries the next one.
- `dev.mjs` exports `createDevServer({ root, port }) → { url, close() }` for tests.

- [ ] **Step 1: Write failing tests** (run the CLI with `execFileSync` on a temp copy of `tests/fixtures` plus a symlink or copy of `assets` paths it needs):
  - `build then check passes`. `check after hand edit fails and names the file`, then `build` restores it and `check` passes.
  - `check ignores CRLF`: rewrite one generated file with `\r\n` and `check` still exits 0.
  - `new creates a buildable project`: `new my-piece` gives a file containing `title: My Piece`, and `build` exits 0. `new my-piece` again exits 1. `new "Bad Name"` exits 1.
  - `bad content exits 1 with file and field`.
  - `dev serves, injects reload, survives a bad save`: start `createDevServer` on the temp dir and fetch `/`, expecting the HTML to contain `/__reload`. Write invalid YAML to a project and wait 400ms; a fetch of `/` returns 200 with the error message text. Fix the file, wait 400ms, and fetch `/` without the error. Check the generated `index.html` on disk never contains `__reload`.
- [ ] **Step 2:** `node --test tests/cli.test.mjs` and expect FAIL.
- [ ] **Step 3: Implement** `site.mjs`, `dev.mjs` and the new-project template. The template is a commented front-matter skeleton listing every field and the media syntax, with an empty body section.
- [ ] **Step 4:** Run the tests again and expect PASS.
- [ ] **Step 5: Commit**: "Add site CLI: build, check, new, dev".
